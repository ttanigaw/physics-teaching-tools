# DESIGN — 問題設計の原則

状態：暫定 v0.1。**技能の習得**と**配置を変えても構造を認識すること**を分けて設計する。

## 1. 問題の変化軸

| 軸 | 意味 | 例 |
|---|---|---|
| P（配置） | 因子・項の位置／順序 | A2の (1,3)、A4の前・後 |
| N（複雑さ） | 因子数・項数・演算数 | 3数→4数→5数 |
| V（数値） | 大きさ、分数、小数、基準値 | 25×4、125×8、0.125×8 |
| F（数の組の分類） | A2では基本系列F1=2×5、F2=25×4、F3=125×8と倍率A/B/Cを区別 | F1A、F1B、F2A、F3C |
| D（分解操作） | A2では基本の組とは独立に、分解の対象と有無を区別 | 25×4（D0）と25×12（D2） |
| K（組合せ） | 使う技能の数・種類 | A2のみ→A2+A1→混合 |
| 発見難度（discovery_difficulty） | 工夫の見えやすさ。IDのD（分解）とは別 | 固定配置→混合→工夫不要の問題も混在 |

原則：**新しい難しさを一度に複数導入しない**。配置を学ぶ段階では数値・技能をなるべく固定する。特にA2では、基本の数の組と倍率（F）、その位置と向き（P）、必要なら数を分解するか（D）、計算方略の選択・実行（O）を区別する。D（旧F6）はFの次の難易度ではなく、**Fと直交する操作軸**である。全22技能の総数は増やさない。

### 主対象と既習事項

主な対象は**15〜16歳**とし、九九（1〜9の整数同士の掛け算）は既習とみなす。したがって、**九九の一問一答のみを独立した練習問題として問題バンクに登録しない**。一方、`2×91×5`のように、九九の知識を利用して式全体の計算順序を工夫する問題は学習目標が異なるため対象とする。各技能で前提とする既習事項と実際に診断すべき技能を区別し、習得済み技能の不要な反復を避ける。

## 2. 学習の進行

1. 発見しやすい一配置を反復し、非効率な計算との差を体験する。
2. 同じ本質で別の配置を扱う。
3. 既習の配置をランダムに混在させ、毎回探索する。
4. 因子数や項数を増やす／有利な組を複数にする。
5. 他の技能と混在させ、工夫しなくてもよい問題も一部入れる。
6. 通常の物理問題への転移を確認する。

「発見型→習得型→探索・転移型→自己点検型→総合型」は学習形式の分類であり、必ず一方向に進む固定カリキュラムではない。

### 学習形式（L1〜L5）の役割

| ID | 形式 | 主たる役割・提示上の注意 |
|---|---|---|
| L1 | 発見型 | 効率の悪い計算も経験し、工夫の存在・価値を自分で見つける。最初に解法を示さない。 |
| L2 | 習得型 | 工夫の内容が分かった後で、計算技術を確実に使えるようにする。 |
| L3 | 探索・転移型 | 同一技能でも位置・表現・数値が変わる問題を混ぜ、毎回構造を探索する。 |
| L4 | 自己点検型 | 概算・範囲・逆算などで正答を見る前の違和感検出・自己修正を練習する。 |
| L5 | 総合型 | 複数技能や工夫不要の問題を混ぜ、工夫も点検も自発的に選ぶ。 |

**L1とL2の区別**：L1の中心は工夫の自力発見、L2の中心は既に理解した工夫の定着。同じ数式でも、提示順やヒントの有無によって学習形式が変わる。

## 3. 優先モジュール A2：乗算順序

3因子で、有利な2因子の位置は (1,2)、(1,3)、(2,3) の**全3通り**。導入では (1,3) から始め、(2,3) を追加し、(1,2) も含む混合へ。

4因子では (1,2)、(1,3)、(1,4)、(2,3)、(2,4)、(3,4) の**全6通り**。初期は有利な組を一つに絞り、位置だけを変える。その後で2組同時に有利な組合せがある式（例：25×8×4×125）や、複数の効率的解法を許す式に進む。

望ましい問題：順番どおりだと数桁の筆算になるが、25×4=100、125×8=1000、20×5=100 などを先に計算すると容易になる。すべてを同じ数の組にしない。

A2の具体的な配置・学習順序・問題候補・評価・品質基準は [A2詳細設計](A2_MULTIPLICATION_ORDER.md) に記す。なお、(1,2)のように左から計算してもすでに効率的な例は、発見型の中心ではなく対照・探索判断の役割を持たせる。

## 4. 優先モジュール A4：分配法則の逆利用

2項 `a×b+c×d` の共通因子を、次の4配置で表現する。

| 配置 | 形式 |
|---|---|
| 前・前 | a×b + a×c |
| 後・後 | b×a + c×a |
| 前・後 | a×b + c×a |
| 後・前 | b×a + a×c |

最初は前・前で認識しやすくし、後・後、混在2種、4配置のランダム混合へ。その後、3項以上、加減算、残りの和が10・50・100以外にもなる問題へ。例：37×48+52×37=37×100。

## 5. 発見型の実施上の注意

- 最初から「先に25と4を掛けよ」「共通因子でくくれ」と指示しない。
- 同じ構造を複数問で経験させ、簡単な方法に気づいた位置・きっかけを観察する。
- 苦労の反復が目的化しないよう、軽いヒント→比較解法→明示説明を使う。
- 学生用の題名や問題順で答えの方略が漏れないか確認する。
- 工夫した解法が唯一の正解とは限らない。別の正当な効率的解法を許容する。

### 工夫による計算負担軽減を確認する

発見型の問題を作る際は、**工夫しない代表的な解法**と**工夫した解法**を実際に比較し、少なくとも次の観点を点検する。

- 筆算を要する乗除算等の回数
- 途中で扱う数の大きさ・桁数
- 小数・分数・根号の処理や近似の負担
- 工夫した解法の短さと誤りにくさ

必ずしも数値のスコアにせず、「なぜ工夫する価値があるのか」を説明できることを採用の目安とする。工夫しなくても簡単な問題は、発見型の中心問題にせず、総合型での解法選択の練習などに活用する。

## 6. 作問時の記録項目（将来の構造化データ）

最低限、`problem_id`、主要技能ID、因子数・項数、配置コード、前提技能・数の組の難度、対象学習形式、式、正答、代表的な工夫、自己点検の手がかり、想定誤答、難易度、公開状態を記録する。問題データとPDF・CBTの表示は可能な範囲で分離するが、**初期に高度な問題生成基盤を構築しない**。

### 問題バンクと配布用セットを分離する

**必要な問題の総数を先に固定せず**、下位技能・配置・数値・認識・実行・自己点検の診断目的に応じて問題バンクを拡充する。教材側で準備する問題数と、各学習者が実際に解く問題数を区別する。紙のプリントはバンクの一部を目的別に配置し、将来のCBDでは同じバンクから苦手な要素を重点的に出題する。

A2の当初の「全48問」は位置の網羅を主に想定した仮配分であり、**下位技能を網羅する完成目標としては撤回**する。Fの系列と倍率、Pの位置と向き、Dの分解操作などを組み合わせる際も、全軸の直積を機械的に出題する必要はない。問題バンクの規模は品質と診断に必要な数から決定する。

### 問題IDの命名思想（A1・A4・B・C・R系列にも適用）

**IDは無意味な通し番号ではなく、問題の数学的構造と教育上の診断対象を表現する分類コードとする。** 数値の違いだけで同じ構造と見なせる問題には、同一の接頭辞を割り当て、末尾の`-01`、`-02`など**2桁の連番**だけで区別する。

今後の各技能モジュールでは、問題を作り始める前に次を設計する。

1. **主要技能コード**：A1、A2、A4、R5など。今後の技能IDは[SKILLS](SKILLS.md)に従う。
2. **独立した下位要素**：前提技能の種類／難度、数式の構造、要素の位置・順序、別途必要な操作の有無など。*それぞれを独立に練習・診断する価値があるか*を見極める。
3. **短く一貫した固定長に近いコード**：各軸のコード長のばらつきを極力抑え、情報の重複を避ける。例えば順序が位置コードに含まれるなら、別にAB/BAを付けない。長い自然言語・可変の情報をIDに詰め込まない。
4. **詳細パターンと数値違いの分離**：数値が異なっても同じ構造なら最後の2桁だけを増やす。必ずしも各パターンに複数問題を作る必要はなく、1問だけなら`-01`だけでよい。
5. **重複・安定性**：同一IDの重複および同一数式の意図しない二重登録を防ぐ。命名規則の改訂時は旧→新IDの対応を明示し、公開・運用後は無断で付け替えない。

**全モジュールにA2のF/P/Dという文字をそのまま使わせるわけではない。** A1の約分、A4の共通因子、R5の有理化などでは、それぞれの数学的構造に合った短いコード表を定義する。**共通なのは「分類軸の独立性」「短く読めるコード」「末尾2桁は同一詳細パターン内の数値違い」という思想**である。長くなりすぎる特殊問題や、同じ接頭辞に100以上の問題が必要な場合はユーザーと相談して拡張する。

**A2の確定済み暫定形式**：`A2-F1A-N3P13-D0-01`（技能・基本系列と倍率・因子数と位置／向き・分解・連番）。`F1B`には20×5と2×50をともに含め、どちらを10倍したかはIDで区別しない。`D1`/`D2`はPに記した第1／第2の因子の分解であり、10倍・1/10倍などの倍率変更だけでは分解としない。詳細・コード表・複合組の扱いは [A2詳細設計](A2_MULTIPLICATION_ORDER.md#41-問題idの構造) を参照。

学習形式L、自己点検M、ヒント・想定誤答、発見難度、掲載順、出題・配布先、倍率を変えた因子や10の指数などは**変化し得る属性として別の問題メタデータ**に保持する。これにより同じIDの問題をPDFとCBDの両方で使い、技能別の誤答傾向を比較できる。

## 6.1 将来のCBT/CBDに向けた問題の診断タグ

印刷用の問題にも、後から適応型CBT/CBDに転用できるよう、**前提技能・配置・学習形式・自己点検方法・想定するつまずき**を記述可能にする。単一の難易度ラベルだけでは、学習者ごとの得意不得意を把握できない。

将来は回答傾向に応じて「前提となる2数の練習へ戻る」「位置だけを変えて再確認する」「複合問題へ進む」「自己点検を促す」等の出題分岐を検討する。各段階の判定には複数の問題を使い、偶然の誤答、別解法、ヒントの影響を考慮する。

**現段階ではデータ構造や適応アルゴリズムは未実装・未確定**。プリント制作を優先し、詳細は [A2詳細設計](A2_MULTIPLICATION_ORDER.md) と [ASSESSMENT](ASSESSMENT.md) に記す。

## 7. プリント制作の原則

- 学生用／解答・解説／教員用資料を分ける。
- 発見段階では余計な解法誘導をしない。必要な自己点検欄は段階に応じて入れる。
- 書き込む余白、1回に解く問題数、答えの見えにくさ、印刷コストを確認する。
- 概算・数値予測に関するヒントは、発見前に見せると種明かしになる場合がある。
